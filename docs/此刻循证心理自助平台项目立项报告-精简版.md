# “此刻”循证心理自助对话平台项目立项报告（精简版）

**文件版本：** V1.0
**编制日期：** 2026 年 8 月 16 日
**项目性质：** 心理自助产品介绍与一期立项方案

## 一、项目简介

“此刻”拟建设一套面向移动端用户的循证心理自助对话平台。产品以自然对话为入口，帮助用户表达和梳理当前困扰，并在适合的情况下，引导用户理解心理知识、学习具体技能、完成小型练习和记录反馈。系统不替代心理咨询师、心理治疗师或精神科医生，不提供诊断、处方和药物调整建议；遇到自伤、他伤或其他急性风险时，应优先停止普通教学并提示现实求助路径。

项目要解决的核心问题是：传统心理课程专业但难以坚持，普通 AI 聊天自然但缺少方法约束和专业依据，简单 RAG 又只能回答“书中写了什么”，无法判断用户此刻更需要倾听、澄清、学习还是练习。因此，本项目不是单纯建设一个心理聊天机器人，而是建设一套“自然对话、专业干预、证据溯源、安全边界和用户反馈”相结合的心理自助系统。

## 二、产品定位与核心形态

产品可以概括为：**以陪伴对话为外在体验，以循证心理干预协议为专业内核，以知识库和结构化练习为内容载体，以安全、隐私、审核和评估为底座。**

用户侧主要包括两种体验。默认的“陪伴对话”先回应用户和当前情境，一次只推进一个问题或行动，避免机械展示知识；“知识伴读”面向希望深入理解的用户，提供心理原理、技能卡片、练习步骤以及可展开的书本章节和页码来源。两种模式共享同一套会话状态、专业知识、安全规则和练习记录，不是相互割裂的两个系统。

平台底层采用独立干预包设计。第一期以通用心理支持和 DBT 干预包为主，后续可增加 CBT、CBT-I 等干预包。每个干预包都必须具有自己的适用范围、权威来源、检索规则、干预流程、练习、审核状态、评测集和版本记录，不能让大模型在 CBT、DBT、ACT 等方法之间自由混合。AI 可以提出一到两个候选方法并解释理由，最终由用户确认。

## 三、系统核心逻辑

一次完整互动遵循以下顺序：

```text
用户表达
→ 安全和使用边界识别
→ 理解当前需求与会话状态
→ 判断需要倾听、稳定、澄清、学习还是练习
→ 选择通用支持或当前专业干预包
→ 检索与本轮目标相关的专业证据
→ 生成自然、简短、可执行的回应
→ 校验引用、安全、重复性和表达边界
→ 用户反馈是否有帮助
→ 继续、调整、切换方法或转介真人
```

其中，大模型主要负责理解自然语言和组织表达；RAG 负责为专业解释和练习提供依据；干预引擎负责决定当前应该做什么；安全系统始终先于检索和模型运行。产品专业性不能只依赖提示词，也不能把“找到相似片段”当成回答正确。

## 四、现有基础与主要差距

现有原型已经具备移动端页面、陪伴对话与知识伴读、DBT 技能导航、结构化练习、带出处检索、安全优先路由、有限多轮会话和基础工程测试。两册 DBT 资料共登记 1,176 个 PDF 页面，其中 1,156 个页面具有可检索内容，形成 1,189 个原文精确片段和 1,156 个父级上下文块，共覆盖 681,595 个 OCR 字符。纳入范围内的机械字符覆盖率为 100%，未发现孤立非空页面。

这些指标证明两册资料已经进入可追溯知识底座，但不代表 OCR 已逐页人工校对，也不代表专业内容已经验收。目前 18 个结构化导航节点尚未完成 DBT 专业人员审核；危机路由尚未经过独立临床红队和真实转介演练；练习记录主要保存在浏览器本地；账号、加密读写、后台权限、数据导出删除和正式运维仍需产品化建设；两册资料的商业使用授权也需要甲方确认。

## 五、一期建设与交付

一期目标是在现有原型基础上，形成一个可以由甲方和专业人员正式评审，并可供小范围受控体验的 DBT 心理自助版本。重点不是继续增加大量功能，而是完成从自然表达、安全判断、方法选择、证据调用、练习反馈到记录回顾的完整闭环。

| 一期重点 | 主要内容 |
| --- | --- |
| 用户端 | 移动端 H5、陪伴对话、知识伴读、技能、练习、记录和来源查看 |
| DBT 干预包 | 两册资料知识包、技能目录、核心练习、适用规则、来源与内容版本 |
| 会话系统 | 当前需求、目标、干预状态、上次反馈和重复未解决识别 |
| 安全系统 | 自伤、他伤、失控、诊断和用药边界，以及现实求助提示 |
| 数据与审核 | 用户同意、练习记录、内容审核、版本记录和基础审计能力 |
| 评测与部署 | 固定测试集、专业审核、安全红队、移动端测试和受控部署环境 |

一期交付物应包括可运行系统、代码和部署文档、知识包及构建工具、内容和来源清单、安全规则、专业审核表、冻结测试集、测试结果、已知问题清单以及小范围试用说明。正式工期和费用需要在账号、后台、课程、专业人员端和部署方式确定后另行核算。

## 六、评估与验收重点

项目验收需要区分工程、专业、安全和真实效果，不能用一类指标代替另一类结论。

| 评估方向 | 建议验收重点 |
| --- | --- |
| 知识完整性 | 页面有来源记录，关键内容人工核对，引用可返回原扫描页 |
| 检索与引用 | 专家问题集 Recall@5 建议不低于 90%，主要专业主张来源覆盖率和支持率建议不低于 95% |
| 对话质量 | 能够理解用户、避免套话和重复、一次只推进一个重点，并根据反馈调整 |
| 方法一致性 | 所有专业练习来自当前确认的干预包，固定测试中不得无规则混合流派 |
| 安全边界 | 明确危机固定测试不得漏报，不提供诊断、处方和擅自调药建议 |
| 移动端体验 | 约定手机和浏览器能够完成对话、练习、来源和记录等核心任务 |
| 数据隐私 | 明确数据用途、保存位置、第三方模型处理、访问、导出和删除方式 |

上述测试只能证明系统在约定版本和测试范围内达到工程及产品要求，不能直接证明临床疗效。若未来需要宣传治疗焦虑、抑郁或其他疾病，必须针对目标人群、完整干预协议和当前软件版本另行开展符合要求的效果与不伤害研究。

## 七、甲方立项前需要确认

甲方需要在正式外部试用前确认目标用户是否限定为成年人、一期是否只建设 DBT、书籍和课程是否具有商业加工授权、由谁负责专业内容审核、危机情况下采用什么人工和现实转介路径、用户数据保存在哪里及保存多久、是否建设专业人员端，以及产品允许使用哪些宣传表述。这些问题会直接影响功能、工期、费用和责任边界，不能由技术团队自行推定。

## 八、立项建议

现有原型已经验证整书知识摄取、证据检索、安全优先编排和双模式交互的工程可行性，项目具备继续建设基础。建议甲方批准一期产品化建设，但一期定位应保持为“成年用户心理自助与 DBT 技能学习”，先完成内容授权、专业审核、安全红队、隐私方案和受控试用，再根据真实反馈决定是否增加 CBT 等其他干预包。

项目最终要形成的不是一个“什么都能聊”的 AI，也不是一个只会展示书本摘录的知识库，而是一套**对话自然、方法明确、过程可执行、知识可追溯、风险有边界、结果可评估的循证心理自助平台**。
