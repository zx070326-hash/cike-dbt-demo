# 此刻 V2：从第一性原理重构 DBT 心理自助产品

更新日期：2026-08-12

## 1. 我们真正要完成的任务

用户不是来“查询一本书”，而是在一个具体时刻需要：先保证安全，澄清自己想改变什么，从可靠的 DBT 依据中选择一个暂定技能，完成一个负担较低的练习，并知道下一步以及何时应离开自助工具寻求真人帮助。

因此产品的核心不是聊天、RAG、Agent 或 Wiki 中任何一个技术名词，而是以下可验证闭环：

```text
当前情境 -> 安全判断 -> 目标澄清 -> 技能选择 -> 原书依据
          -> 结构化练习 -> 用户确认 -> 结果记录/退出
```

AI 只负责受约束的理解、组织和表达。来源真相、安全规则、状态转换、引用校验和数据权限不交给模型自由决定。

## 2. 七条不可破坏的不变量

1. **来源不变量**：书内专业结论必须解析到原书、PDF 页、印刷页、原文字符区间；Wiki 不是最终证据。
2. **全书覆盖不变量**：每个非空 OCR 字符至少属于一个证据片段；空白页也必须在来源清单中出现。
3. **主张不变量**：生成回答中的 DBT 定义、适用条件和步骤必须绑定本轮证据 ID；无法支持时澄清、降级或停止。
4. **情境不变量**：用户明确陈述与系统推断分开保存；系统不得代填用户没有说出的原因、动机或事实。
5. **安全不变量**：危机和诊疗边界先于检索与模型；任何生成结果都不能改变确定性转介路径。
6. **会话不变量**：每次会话只围绕一个目标，以技能、练习、行动或退出结束；不以无限陪聊作为留存机制。
7. **数据不变量**：默认不持久化原始聊天；只在单独同意后保存最小化、结构化、可导出和可删除的数据。

## 3. V2 五层架构

### 3.1 来源层：不可变证据

- 原始扫描 PDF 和页面图进入私有对象存储。
- OCR 保存文本块、坐标、阅读顺序、置信度和处理版本。
- 每次摄取生成来源文件 SHA-256、PDF 页数、空白页和失败页清单。
- 原始证据只追加新版本，不在原地覆盖；发布新知识版本时原子切换。

### 3.2 知识层：原文片段 + Evidence Wiki

```text
PDF 页面
  -> OCR 页面文本
  -> source-exact chunks（完整字符覆盖）
  -> 章节/技能/练习单节点
  -> Evidence Wiki 关系
  -> 可选向量与关键词索引
```

V2 知识包包含 1189 个来源精确片段，覆盖两册 1156 个非空页面的 681595 个字符；1176 个 PDF 页均在清单中，20 个空白页单独记录。目前 18 个 Wiki 节点只承担检索导航，状态为 `source-linked-unreviewed`，没有把未经审核的 LLM 摘要伪装成权威知识。

未来的 LLM Wiki 发布流程必须是：候选原文 -> 生成结构化草稿 -> 逐主张引用校验 -> 专业人员审核 -> 发布。未经审核的节点可以帮助召回，但不能直接成为用户可见的专业结论。

### 3.3 运行时：安全优先的受控编排

```text
输入验证
  -> 确定性危机/诊疗边界
  -> 会话状态与用户目标
  -> Wiki 查询扩展
  -> 关键词 + 语义混合召回
  -> 重排 + 同章节父块补全
  -> evidence bundle
  -> 闭源模型 JSON 生成
  -> 逐主张支持度校验
  -> 输出安全复检
  -> 回答、来源和下一状态
```

当前已把 HTTP 路由与应用编排分离，V2 运行时已改为检索来源精确片段，而不是每页固定前 420 字。下一步的生产增强是外部 embedding/rerank 接口和逐主张引用数据结构；它们不得改变本地稀疏检索和模板降级能力。

### 3.4 工作流层：技能不是一段聊天

每个结构化练习是有版本的有限状态机，包含字段、跳过规则、进入条件、退出条件、Wiki 节点和专业审核状态。当前“核对事实”为 Demo 可用；STOP、TIP、相反行为、问题解决、DEAR MAN、行为链和全然接纳已经建立结构定义，但在专业审核前不得作为已完成的正式干预流程发布。

会话状态建议固定为：

```text
start -> clarify_goal -> recommend_skill -> confirm_skill
      -> practice -> reflect -> save_or_discard -> close

任意状态 -> safety_escalation
任意状态 -> user_exit
```

### 3.5 产品与数据层

普通用户首页使用四个入口，而不是工程证据看板：

1. 此刻需要帮助：高强度情况下快速稳定和安全入口。
2. 描述一个具体困扰：短对话选择技能。
3. DBT 技能：按正念、痛苦耐受、情绪调节、人际效能浏览。
4. 练习、记录与安全计划：独立于聊天使用。

记录采用服务端持久化时，只保存加密的结构化练习、短会话摘要和安全计划；原始聊天不作为默认记录。数据库已区分用户、同意、练习记录、会话摘要、安全计划、内容版本、专业审核和无敏感正文的审计事件。

## 4. 技术栈边界

| 层 | 当前/推荐实现 | 边界 |
|---|---|---|
| H5 | Next.js/Vinext + TypeScript | 保持手机优先和无障碍 |
| 离线摄取 | Python + OCR 管线 | 生成不可变来源和覆盖报告 |
| Demo 检索 | Evidence Wiki 扩展 + BM25 风格稀疏检索 | 无模型密钥也必须工作 |
| 生产检索 | 中文关键词 + embeddings + RRF + reranker | 向量召回不能单独决定证据 |
| 生成 | 可替换闭源模型适配器 | 只接收 evidence bundle，强制结构化输出 |
| 用户数据 | D1 结构化元数据 + 应用层加密载荷 | 不保存默认原始聊天 |
| 书籍资产 | 私有 R2 | 授权未确认前不公开原页和全文 |
| 复杂知识检索 | 可独立演进为 PostgreSQL/pgvector 服务 | 不让平台存储限制污染领域模型 |

## 5. “完全完成”的验收矩阵

### 工程可自行证明

- PDF 页清单覆盖率 100%。
- 非空 OCR 字符片段覆盖率 100%。
- 孤立非空页面为 0，Wiki 证据断链为 0。
- 所有用户可见 DBT 主张的引用解析率 100%。
- 危机路径在检索和模型之前运行。
- 模型不可用、超时、输出无效或引用失败时能确定性降级。
- 移动端可完成“目标—技能—练习—保存/丢弃—退出”的闭环。
- 用户可以查看同意版本、导出和删除自己的持久化记录。

### 必须由外部角色提供证据

- 出版方或权利方确认商业使用范围。
- DBT 专业人员审核 Wiki 主张、技能路由和全部正式工作流。
- 独立团队完成危机漏检/误检红队与真实转介演练。
- 甲方确定目标人群、人工责任人、隐私政策、保存期限和供应商数据边界。
- 法律、医疗器械/诊疗属性和生成式 AI 服务义务由有资质人员确认。

没有这些外部证据时，可以说“工程闭环完成”，不能说“临床安全、合规或治疗有效已经完成”。

## 6. 迁移顺序

1. **知识地基**：V2 来源精确片段、覆盖验证和 Evidence Wiki。已落地。
2. **编排边界**：HTTP、应用编排、检索、模型和安全模块解耦。基础已落地。
3. **引用升级**：回答从“末尾列页面”升级为逐主张引用与原文高亮。
4. **工作流引擎**：把现有核对事实页面改为通用状态机，逐个审核并开放其他技能。
5. **信息架构**：四入口首页、短会话、技能库、练习记录、安全计划；证据板只保留为内部调试模式。
6. **账户与数据权利**：确认身份方案和隐私政策后接入加密持久化、导出、删除和审计。
7. **生产检索与评测**：混合检索、rerank、固定金标集、持续质量门禁。
8. **外部试用门禁**：版权、专业审核、独立红队、转介演练和合规确认全部有可审计签收。
