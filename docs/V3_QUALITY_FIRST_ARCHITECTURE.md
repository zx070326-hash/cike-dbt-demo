# V3：质量优先的 DBT 自助对话架构

## 1. 产品目标

系统不是“会聊心理问题的通用模型”，也不是自动诊疗工具。它的职责只有五件事：

1. 先识别危机、诊疗和不适用边界；
2. 判断用户此刻更需要被听见、稳定、澄清、学习还是练习；
3. 在书内选择一个最小且合适的 DBT 切入点；
4. 用自然语言推进一小步，并把专业主张绑定到原书证据；
5. 让用户可以检查来源、退出、换方向或转向真人帮助。

检索更多片段、生成更长回答、使用更多 Agent，都不是目标本身。

## 2. 运行时决策链

```text
输入归一化与历史压缩
  -> 确定性安全门（危机 / 他人安全 / 诊疗与用药 / 年龄与范围）
  -> 输入理解（自我体验 / DBT 学习 / 日常对话 / 明确无关 / 不确定）
  -> 会话需要状态（listen / stabilize / clarify / learn / practice）
  -> DBT 技能候选与适用性判断
  -> 混合候选检索（词面 + 概念 + 可选语义）
  -> 章节父块补全、来源质量过滤与重排
  -> Evidence Bundle（技能卡 + 原文片段 + 可声明主张）
  -> 模式化表达（陪伴对话 / 知识伴读）
  -> 逐主张引用、重复性、安全与边界复核
  -> 用户可见回答 + 下一步 + 可展开来源 + 决策追踪
```

模型可以参与语言组织和候选判断，但不能越过安全门、伪造事实、改变引用、把未经审核的 Wiki 草稿当成专业结论。

### 2.1 输入理解契约

输入理解层只判断用户正在把什么带进对话，不负责选择技能，也不生成回答。它输出稳定的结构化结果：作用域、主体、自我体验信号、情绪信号、情境信号、置信度和原因码。

- 危机、他伤、诊断和用药仍在这一层之前确定性处理。
- 自我体验即使暂时无法映射到某个技能，也进入一次低负担澄清；“不确定”不能自动降级成“范围之外”。
- 只有明确的一般知识、第三人称描述或无关对象请求才进入范围外。
- “陪伴对话”和“知识伴读”共享同一输入理解和技能决策，只改变后续表达顺序。
- 用户重复同一表达时，把它视为上一轮可能没有解决需要的反馈；不得原样重复同一张卡。
- 情绪词只作为输入信号，不能单独证明主体是用户，也不能直接决定 DBT 技能。

## 3. 不变量

### 3.1 证据

- 两册书的 source-exact chunks 是不可变的事实层；清洗只生成派生字段，不覆盖原 OCR。
- 每个用户可见的 DBT 定义、适用条件和练习步骤，都必须绑定一个或多个 chunk ID。
- Wiki/技能卡只有在 `professionally-reviewed` 后，才能作为稳定的专业表述；未审核内容只能帮助召回或标记为草稿。
- 引用存在不等于引用正确；必须验证引用片段是否支持对应主张。

### 3.2 对话

- 情绪承接只使用用户已经说出的信息，不猜原因、动机、诊断或他人意图。
- 每轮只推进一个主要目标；默认一个技能、一张卡、一个问题或一个动作。
- 陪伴模式先回应人，再提供可折叠的知识；伴读模式先解释，再给练习与来源。
- 用户可以继续倾诉、澄清原因、立即练习、换一个方向或查看来源。

### 3.3 安全

- 危机、他人伤害和诊疗/用药请求在检索与模型调用前处理。
- 真实自然语言改写必须进入安全回归集，不能只测试关键词样例。
- 免责声明不是安全机制；结果必须给出可执行的现实世界下一步。

## 4. 质量门

### 4.1 组件指标

- 安全：危机召回、诊疗边界召回、他人安全召回、误报率。
- 会话决策：需要状态准确率、技能候选 Top-1/Top-3、追问必要性。
- 输入理解：自我体验召回、第三人称/无关请求误接率、双模式作用域一致率、重复未解决恢复率。
- 检索：Recall@5、MRR、父章节命中、低质量来源占比。
- 引用：主张覆盖率、引用支持率、页码与 chunk ID 完整率。
- 对话：是否先承接、是否只推进一步、是否重复、是否能自然继续。

### 4.2 端到端场景

- 模糊低落和疲惫；
- 关系依恋与被拒绝；
- 愤怒、摔东西与事后后悔；
- 诊断和用药询问；
- 间接自伤与直接危机；
- 指定技能学习；
- 多轮练习后无效、略有变化或更难受；
- 模型超时、拒绝生成与无检索结果。

任何新依赖或新检索路线，只有在冻结评测集上改善目标指标且不破坏安全、延迟和可追溯性时才保留。

## 5. 现阶段不接受的捷径

- 不把“所有页面已摄取”当成知识质量完成；
- 不把同一模型的自我检查当成独立事实证明；
- 不用自动生成的 LLM Wiki 替代专业审核；
- 不以更长提示词掩盖路由、证据结构和状态管理缺陷；
- 不在没有对照评测的情况下迁移到重型 RAG 或 Agent 框架。
